# Hand-Drawn Tech Note Skill

Turn technical content into a hand-drawn engineering note that feels readable, structured, and worth saving.

This style is not about making technology "cute." It is about making technical reasoning feel human: a page with a strong title, a clear judgment, highlighted evidence, lightweight diagrams, handwritten annotations, and a final takeaway.

## 1. Best Use Cases

Use this style for:

- AI model release analysis
- Agent, workflow, or architecture breakdowns
- Technical source-article summaries
- Developer experience retrospectives
- Product mechanism explanations
- Personal technical judgment and builder logs

Avoid this style for:

- Pure marketing posters
- SaaS homepage hero sections
- Large 3D technology illustrations
- Complex UI mockups
- Covers with only a slogan and no explanation

## 2. Two Style Branches

### A. Long-Form Tech Note

Use this for deep technical explainers such as AI drawing series, source-article breakdowns, and engineering analysis posts.

Keywords:

- first page of a technical article
- engineering analysis
- research note
- credible information
- clear hierarchy
- save-worthy

Visual traits:

- warm off-white or aged beige paper
- subtle paper grain and weak grid texture
- left-aligned editorial composition
- large headline, thesis sentence, and short body text
- pale purple, pale yellow, and soft pink marker highlights
- light gray code chips
- orange handwritten annotations and arrows
- lightweight comparison boxes, flow notes, or mechanism modules
- clean source link at the bottom

### B. Builder Log Notebook

Use this for AI-native builder logs, model observations, personal architecture judgment, and field-note style posts.

Keywords:

- builder log
- field notes
- personal notebook
- architecture judgment
- first reaction
- handwritten annotations

Visual traits:

- warm aged paper
- ruled notebook lines
- left red margin line
- binder holes or loose-leaf paper edge
- uneven hand-drawn borders
- sticky notes, arrows, underlines, and small handwritten marks
- large hand-lettered title
- green hand-drawn conclusion strip

## 3. Visual Grammar

### Paper

Use warm off-white or aged beige paper. Add subtle grain, weak grid texture, or faint ruled lines. The texture should support the text, not compete with it.

### Typography

The title should feel editorial and serious, not childish. Use dark ink black for main text and deep technical blue for important technical terms.

### Highlights

Use marker-style highlights to create semantic hierarchy:

- pale purple for the main point of view
- pale yellow for mechanism or explanation
- soft pink for caution, tension, or a counterintuitive point

### Annotations

Use orange annotations sparingly:

- arrows
- underlines
- small stars
- marginal notes
- sketchy frames

Do not fill the entire page with decorative handwriting.

### Information Modules

Keep modules lightweight:

- small comparison boxes
- 2-3 step flows
- code chips
- tiny conclusion cards

Modules should support the body text. They should not become the main visual subject.

## 4. Standard Cover Structure

A cover can follow this order:

1. Small orange series label at the top-left  
   Example: `AI Drawing #001`

2. Muted gray source label at the top-right  
   Example: `Source / Anthropic`  
   Do not underline it. Do not add a border. Do not make it decorative.

3. Brand or product lockup  
   Example: `Anthropic | Claude Code`, `OpenAI | Codex`  
   Use a recognizable logo or symbolic mark.

4. Main headline  
   Mostly dark ink black, with the key technical term in deep blue.

5. Core judgment  
   Prefer a sentence with contrast, such as "not X, but Y."

6. Short intro  
   1-2 short paragraphs explaining why the reader should care.

7. Lightweight mechanism module  
   Code chips, a comparison box, or a small flow.

8. Bottom source link  
   Keep it small and gray. Do not repeat hashtags or the series label.

## 5. Prompt Formula

Use this structure when writing image prompts:

```text
canvas ratio ->
paper material ->
overall mood ->
top labels ->
brand/source signal ->
main headline ->
core judgment ->
intro paragraph ->
highlight system ->
lightweight mechanism modules ->
annotation elements ->
bottom conclusion or source ->
negative constraints
```

## 6. Reusable Prompt Template

```text
Create a vertical social media image in a hand-drawn long-form technical note style, as if it were the first page of a thoughtful developer article rather than a flashy poster.

Use a warm off-white / aged beige paper background with subtle paper grain and a very light notebook grid texture. The page should feel calm, readable, information-dense, and highly save-worthy, like a technical writer's annotated engineering note.

Use an editorial left-aligned composition with clear hierarchy:
- a small orange outlined label at the top-left
- a muted gray source label at the top-right
- a clear brand/product lockup near the top
- a large serious headline in dark ink black
- deep technical blue emphasis for the key technical term
- a sharp thesis sentence beneath the headline
- a short article-style intro paragraph
- 2-3 lightweight engineering-note modules such as code chips, comparison notes, or a small mechanism flow
- a few restrained orange handwritten annotations or arrows
- a clean gray source link at the bottom

Use pale purple, pale yellow, and soft pink marker-style highlights behind important phrases. Keep visual modules small and supportive. The body should feel like a readable technical article, not an infographic.

Visual style requirements:
- warm beige paper
- subtle grid or notebook texture
- dark ink typography
- deep technical blue emphasis
- orange handwritten annotations
- pale marker highlights
- light gray code chips
- sketch-light borders
- strong editorial judgment
- high readability

Avoid:
photorealistic people, glossy 3D render, corporate tech gradient poster, clean SaaS landing page, neon cyberpunk, blue-white generic AI poster, large decorative icons, cluttered UI, table-heavy lecture page, empty slogan-only cover.
```

## 7. Failure Checklist

If the generated image has these problems, the prompt is not specific enough:

- Missing official logo or product mark
- Font is too large and the page feels empty
- Source label is underlined or over-decorated
- Bottom repeats hashtags or the series number
- Cards are too large and overpower the body text
- Overall look becomes a generic blue-white AI poster
- It looks like a slide deck instead of a technical notebook page
- Too many icons make the reading path unclear
- The image has a slogan but no explanatory structure

## 8. One-Sentence Rule

Use the friendliness of hand-drawn notes to carry the density of technical writing.
